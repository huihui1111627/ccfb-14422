# 灯塔航标专网 OSPF 路由模拟

一片海区的灯塔与航标站通过自建无线专网回传设备状态，链路受天气影响时好时坏。本项目用 Go
实现了一个 OSPF 路由协议引擎，把几十个站点的路由进程放进一个进程里，由确定性事件队列驱动报文
收发，并提供一个查看拓扑、邻居状态、链路状态库与路由表的页面。

一次构建即可得到三样东西：

- `cmd/web` —— 浏览器页面，实时查看拓扑、邻居、链路状态库、路由表；
- `cmd/verify` —— 固定随机种子的天气回放验证器，几千个天气事件，逐条核对协议不变量；
- `internal/...` —— 协议引擎、事件引擎与验证逻辑本身。

## 快速开始

```sh
make test        # 运行全部单元测试与协议验证（含可复现性与不变量检查）
make verify      # 命令行跑一次完整回放（约 3500 个天气事件）
make web         # 启动页面，访问 http://127.0.0.1:8099
```

只依赖 Go 标准库（1.26+），不需要任何第三方包，也不联网。

## 验证器做了什么

`cmd/verify` 用固定种子生成一条天气脚本（约每秒一个事件，一小时约 3500 个），按确定性顺序回放：
每处理完一批报文，就核对下列不变量，发现违例则报告具体时刻、区域与站点：

- **链路状态库逐条一致**：同一区域、同一连通分量内的所有站点，按序号、校验和与报文内容比较，
  数据库必须逐条相同。老化时间按协议允许漂移，因此不参与比较。区域被天气切断时，两侧本来
  就无法交换区域内通告，比较只在连通分量内进行。
- **邻居状态变化序列合法**：每一次状态转移都对照 RFC 2328 的状态转移表校验。
- **增量最短路径树等于整棵重算**：每台设备每个区域，比较增量维护的距离图与从同一数据库
  重新计算的结果，逐节点一致。
- **泛洪与重传统计**：每条链路状态通告被泛洪、重传、接收的次数都会汇总。
- **同一种子可复现**：回放结束时对整个网络数据库与路由表取指纹，同一颗种子两次运行指纹一致。

运行示例：

```sh
# 单个种子，带每类最多 10 条违例
go run ./cmd/verify -seed 42 -max 10

# 多种子批量，并把泛洪统计写到文件
go run ./cmd/verify -seeds 1,7,42,99 -stats /tmp/flood.json

# 机器可读输出
go run ./cmd/verify -seed 42 -json
```

## 页面

页面分四块：拓扑图、每台的邻居状态、链路状态库、路由表，另有协议事件时间线与泛洪统计。

- **拓扑图**：按区域着色，链路颜色反映天气（正常/降级/中断），虚链路用虚线；点击站点查看细节。
- **邻居状态**：状态徽标、主从角色、收发 Hello、以及卡住时的具体原因（例如
  `MTU mismatch: local 1400, remote 1500`）。
- **链路状态库**：按区域分页，列出类型、链路标识、通告路由器、序号、老化、校验和与内容摘要。
- **路由表**：目的前缀、类型（区域内/区域间/外部）、开销、下一跳、区域、是否经虚链路。

页面上方可以开始/暂停仿真、单步推进、切换随机种子与天气间隔后重置。

## 设计要点

- **确定性**：单个事件堆，同时刻按入队顺序执行；丢包由「时间与链路」的哈希决定，不依赖全局
  随机数的消费顺序；因此同一颗种子逐字节可复现。
- **老化不占计算**：LSA 记录「存入时的老化值 + 存入时刻」，当前老化按需推导，老化不产生定时事件。
- **增量 SPF**：比较两次计算之间的图差异，变贵的边使其旧子树失效，变便宜或新增的边作为种子
  重新松弛；只有受影响的节点重算。若图的节点集合变化，则自动回退到整棵重算以保证正确。
- **可靠泛洪**：每条发往邻居的通告进入重传表，未确认则周期重传；邻接到达完全状态时，再按
  邻居的数据库描述摘要补发其缺少或较旧的通告，用来闭合链路抖动期间可能出现的缺口。

## 已知取舍

- 广播型接口（DR/BDR 选举）没有建模：海区回传是点对点的专用无线链路，拓扑里全部按点对点处理。
- NSSA（类型 7）在配置里可声明，但类型 7 到类型 5 的转换没有实现；末节与完全末节已完整实现。
- 区域被切断时，两侧数据库允许不同，这是 OSPF 的既定行为；验证器只在连通分量内要求一致。
